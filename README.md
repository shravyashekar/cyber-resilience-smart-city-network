# Cyber Resilience Smart City Network

A self-contained educational simulation for a fictional smart city. It can use generated traffic or a labeled public CSV for detector evaluation, and demonstrates the project proposal's three-tier response and recovery workflow.

## Safety and scope

This is an **educational simulation**. The app does not scan devices, send traffic to real systems, connect to city infrastructure, or change real systems. Streamlit serves the dashboard locally on your computer. City services and response actions are fictional. Traffic is generated by default; an uploaded public CSV can be used for offline detector evaluation. The malware-like scenario is not malware and contains no executable payload.

## Project contents

- `dashboard.py` — Streamlit control panel, topology, detector results and response status.
- `data_generator.py` — seeded synthetic traffic generation.
- `network_topology.py` — fictional NetworkX city graph with standby nodes.
- `anomaly_detector.py` — Isolation Forest training and scoring.
- `self_healing.py` — tier-based failover, safe fallback, isolation and verification.
- `simulation.py` — combines generator, detector and response.
- `benchmark_data.py` — loads a labeled CSV and reports held-out detector metrics.
- `requirements.txt` — Python dependencies.

## Windows PowerShell setup (Python 3.10, VS Code)

1. Extract the downloaded ZIP into your existing `main el` folder. It contains a folder named `Cyber_Resilience_Smart_City_Network`. Open that folder in VS Code, or enter it in PowerShell with `cd .\Cyber_Resilience_Smart_City_Network`.
2. Activate your existing environment if it is not already active. From the project folder, when the environment lives in the parent `main el` folder:

   ```powershell
   ..\venv\Scripts\Activate.ps1
   ```

   If `venv` is inside this project folder instead, use `.\venv\Scripts\Activate.ps1`.

3. Install or confirm the dependencies:

   ```powershell
   python -m pip install -r requirements.txt
   ```

4. Launch the dashboard:

   ```powershell
   python -m streamlit run dashboard.py
   ```

Streamlit will print a local address and may open it in your browser. Press `Ctrl+C` in PowerShell to stop the dashboard.

## Try it

Choose an event and city service in the sidebar, then select **Run city drill**. The city-service cards show each service tier and its state. Tier 1 uses failover, Tier 2 uses safe fallback, and Tier 3 is isolated with its backup on standby. Normal traffic does not trigger a response. Adjust the repeatable run number under **More options** to reproduce a run.

## Use a public Kaggle dataset

The **Traffic data** selector can switch to **Labeled public CSV**. One suitable option is the Kaggle **IoT Intrusion Detection** dataset, which describes labeled IoT network intrusion records based on CICIoT2023. The University of New Brunswick's Canadian Institute for Cybersecurity also lists the original CIC IoT Attack Dataset 2023. See the [Kaggle data card](https://www.kaggle.com/datasets/subhajournal/iotintrusion/versions/1) and the [official CIC dataset list](https://www.unb.ca/cic/datasets/).

Download a CSV from the dataset, choose **Labeled public CSV** in the app, upload the file, select its label column, and select the label that means normal traffic (often `Benign` or `Normal`). The app reads up to 50,000 rows, trains the Isolation Forest on normal-labeled training rows, then reports accuracy, precision, recall, false alarms, missed attacks, and a confusion matrix on a held-out sample. Check the dataset's terms and cite its source in your presentation.

Public IoT intrusion data is a benchmark for network detection; it is not traffic captured from a real hospital or smart city. The city-service graph and response actions remain a simulation. The uploaded data is used for detector evaluation only and stays on the local machine while the app runs.

## Detection and response notes

The Isolation Forest is fit using generated normal records by default, or normal-labeled rows from an uploaded CSV. It flags unusual feature patterns, not real attackers. Its public-CSV metrics use a held-out sample; benchmark results depend on the dataset, selected labels, and features. Responses follow service tier: Tier 1 isolates the affected endpoint and reroutes its links to an active backup; Tier 2 switches to a safe fallback mode; Tier 3 is isolated while its backup stays on standby. The Civic Impact Score is a simple illustrative estimate based on tier and scenario severity; it is not a validated city-risk measure. This is a classroom prototype, not production security or an autonomous real-world response system.
